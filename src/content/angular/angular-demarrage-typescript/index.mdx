# Démarrer avec Angular et TypeScript

Ce module prépare l'environnement de développement et introduit TypeScript ainsi que la structure d'une application Angular moderne. Vous créerez une application standalone, comprendrez les fichiers générés et apprendrez à compiler et servir le projet. Le fil rouge sera un tableau de bord de bibliothèque que les modules suivants enrichiront.

## Objectifs

- Installer Node.js et utiliser npm et Angular CLI.
- Créer et démarrer une application Angular standalone.
- Comprendre les types TypeScript essentiels et l'inférence.
- Lire la structure générée par Angular CLI.
- Distinguer code source, compilation et serveur de développement.
- Créer un premier composant et documenter des commandes reproductibles.

## Prérequis

- Connaissance de base de HTML, CSS et JavaScript.
- Node.js LTS et npm installés.
- Un terminal et un éditeur de code.

## Cours

### TypeScript en bref

TypeScript ajoute une vérification de types au JavaScript. Le compilateur vérifie certaines erreurs avant l'exécution, puis produit du JavaScript. Les annotations de types ne sont généralement pas présentes à l'exécution.

```typescript
const titre: string = "Ma bibliothèque";
let nombreDeLivres: number = 0;
const estOuverte: boolean = true;
const tags: string[] = ["lecture", "favori"];

function saluer(nom: string): string {
  return `Bonjour ${nom}`;
}
```

L'inférence évite les annotations redondantes lorsque la valeur initiale indique déjà le type :

```typescript
const message = "Prêt"; // string
let compteur = 0;        // number
```

Utilisez `const` par défaut, `let` seulement si la variable doit être réaffectée, et évitez `any`, qui désactive la vérification de type sur la valeur.

### Objets et unions

Un `interface` décrit la forme d'un objet :

```typescript
interface Livre {
  id: number;
  titre: string;
  auteur: string;
  lu: boolean;
}

const livre: Livre = {
  id: 1,
  titre: "Le Petit Prince",
  auteur: "Antoine de Saint-Exupéry",
  lu: false,
};
```

Un type union limite une valeur à plusieurs possibilités explicites :

```typescript
type EtatChargement = "initial" | "chargement" | "termine" | "erreur";
let etat: EtatChargement = "initial";
```

Les unions empêchent les chaînes arbitraires et aident l'éditeur à proposer les choix possibles.

### Installer Angular CLI et créer une application

Angular nécessite une version de Node.js prise en charge par la version du framework choisie. Consultez les prérequis Angular et utilisez une version LTS de Node.js. Installez la CLI ou exécutez-la ponctuellement avec `npx` :

```bash
npm install --global @angular/cli
ng version
ng new bibliotheque --standalone --routing --style css
cd bibliotheque
npm start
```

La commande affiche l'adresse du serveur local, habituellement `http://localhost:4200`. Dans un autre terminal, `ng serve` démarre également le serveur de développement. Arrêtez-le avec Ctrl+C.

Angular CLI génère et configure les dépendances du projet. Le fichier `package-lock.json` fixe leurs versions résolues : conservez-le et utilisez `npm ci` pour une installation reproductible dans un dépôt déjà créé.

### Lire la structure générée

Les fichiers utiles au début sont :

- `src/main.ts` : point d'entrée qui démarre l'application Angular.
- `src/app/app.config.ts` : fournisseurs et configuration globale.
- `src/app/app.routes.ts` : routes de l'application.
- `src/app/app.component.ts` : composant racine.
- `src/app/app.component.html` : template du composant racine, si le projet garde un template séparé.
- `src/styles.css` : styles globaux.
- `angular.json` : configuration de la CLI.
- `package.json` : scripts et dépendances.

Le serveur de développement recompile le projet lors des modifications et signale les erreurs de TypeScript et de template. Une compilation réussie ne garantit cependant pas que l'interface est accessible ou que les scénarios fonctionnent : les modules suivants ajouteront tests et vérifications.

### Composant standalone

Un composant encapsule une partie de l'interface. Il possède une classe TypeScript, un template et éventuellement des styles. Les composants standalone déclarent leurs dépendances directement dans `imports`.

```typescript
import { Component } from "@angular/core";

@Component({
  selector: "app-root",
  standalone: true,
  template: `
    <main>
      <h1>{{ titre }}</h1>
      <p>Une application pour organiser ses lectures.</p>
    </main>
  `,
})
export class AppComponent {
  titre = "Ma bibliothèque";
}
```

Le décorateur `@Component` fournit les métadonnées nécessaires à Angular. Le sélecteur `app-root` est le nom de l'élément utilisé par l'application. L'interpolation `{{ titre }}` affiche une valeur dans le template.

Créez un composant réutilisable avec la CLI :

```bash
ng generate component livres/page-livres
```

La CLI place les fichiers dans l'arborescence du projet et peut mettre à jour les imports. Inspectez le code généré avant de le modifier.

### Scripts npm et construction

`npm start` démarre généralement le serveur configuré dans `package.json`. `ng build` compile l'application pour la production :

```bash
npm ci
npm start
npm run build
```

Exécutez les commandes depuis le dossier qui contient `package.json`. Les fichiers générés se trouvent dans `dist/` et ne doivent pas être modifiés manuellement.

<Callout type="tip">
Après le clonage d'un projet, commencez par `npm ci`, puis lancez le script indiqué par son README. Évitez de modifier les dépendances globales pour corriger une erreur propre à un seul projet.
</Callout>

## Erreurs fréquentes

**Mélanger JavaScript et TypeScript**

Angular utilise TypeScript pour ses composants. Renommer un fichier ne suffit pas à convertir le code : ajoutez des types valides et respectez la configuration du compilateur.

**Utiliser `any` pour faire taire une erreur**

`any` supprime des vérifications utiles. Décrivez plutôt la forme des données avec une interface ou un type union.

**Modifier les fichiers générés**

Ne modifiez ni `dist/` ni `node_modules/`. Changez le code sous `src/`, puis laissez les outils reconstruire les artefacts.

**Oublier le dossier courant**

`npm start` doit être exécuté dans le projet contenant `package.json`. Le message d'erreur de npm aide à repérer un terminal ouvert au mauvais emplacement.

## Exercices

<Exercise n="1.1" title="Vérifier l'environnement Angular">
Relevez les versions de Node.js et npm, vérifiez Angular CLI, créez une application standalone avec routage et styles CSS, puis démarrez-la.
</Exercise>

<Solution>
Utilisez `node --version`, `npm --version` et `ng version`. Créez le projet avec `ng new bibliotheque --standalone --routing --style css`, entrez dans le dossier, puis lancez `npm start`. La page de démarrage doit être servie sans erreur de compilation.
</Solution>

<Exercise n="1.2" title="Modéliser un livre avec TypeScript">
Définissez une interface `Livre` avec un identifiant, un titre, un auteur et un booléen indiquant si le livre est lu. Créez un objet valide et un type union pour l'état de chargement.
</Exercise>

<Solution>
```typescript
interface Livre {
  id: number;
  titre: string;
  auteur: string;
  lu: boolean;
}

type Etat = "initial" | "chargement" | "termine" | "erreur";

const premierLivre: Livre = {
  id: 1,
  titre: "Dune",
  auteur: "Frank Herbert",
  lu: false,
};
```
</Solution>

<Exercise n="1.3" title="Créer le premier composant">
Modifiez le composant racine pour afficher un titre, une phrase de bienvenue et une liste de trois objectifs du tableau de bord. Identifiez le fichier d'entrée et le fichier de configuration du routage.
</Exercise>

<Solution>
Le composant racine déclare une propriété `titre` et affiche `{{ titre }}` dans son template. Les objectifs peuvent d'abord être du HTML statique. Le démarrage est configuré depuis `src/main.ts` et les routes initiales se trouvent dans `src/app/app.routes.ts`.
</Solution>

<Exercise n="1.4" title="Construire pour la production">
Exécutez la compilation de production. Repérez le dossier de sortie et vérifiez qu'aucun fichier généré n'a été ajouté au code source.
</Exercise>

<Solution>
Lancez `npm run build` ou `ng build`. Angular écrit les artefacts de production sous `dist/`. Le code à modifier reste sous `src/`; ne corrigez jamais directement les fichiers compilés.
</Solution>

## Livrable

Une application Angular standalone qui démarre localement, possède un modèle TypeScript `Livre`, affiche une première page de bibliothèque et se compile pour la production.
