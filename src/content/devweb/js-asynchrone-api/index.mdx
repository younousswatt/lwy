# JavaScript — Asynchrone et API

Ce module explore la programmation asynchrone en JavaScript, essentielle pour les opérations qui prennent du temps (requêtes réseau, lectures de fichiers, timers). Il explique les callbacks historiques, les promesses (Promises) modernes, la syntaxe async/await pour un code asynchrone lisible, l'API fetch pour effectuer des requêtes HTTP, la gestion des erreurs asynchrones, et le mécanisme CORS (Cross-Origin Resource Sharing). Ces concepts sont indispensables pour créer des applications web qui communiquent avec des serveurs et des API externes. À l'issue de ce module, vous serez capable de créer une application météo fonctionnelle qui utilise une API réelle.

## Objectifs

- Comprendre la différence entre code synchrone et asynchrone.
- Utiliser les callbacks pour les opérations asynchrones (approche historique).
- Créer et chaîner des promesses (Promise, then, catch, finally).
- Utiliser async/await pour un code asynchrone lisible.
- Effectuer des requêtes HTTP avec l'API fetch.
- Gérer les erreurs asynchrones (try/catch, .catch(), .finally()).
- Comprendre CORS et les restrictions de sécurité du navigateur.

## Prérequis

- JavaScript — Bases (fonctions, callbacks basiques)
- JavaScript — Structures de données (objets, JSON)
- JavaScript — DOM (sélection, modification)
- Fondamentaux du web (HTTP, requêtes et réponses)

## Cours

### Synchrone vs Asynchrone

Le code synchrone s'exécute ligne par ligne, dans l'ordre. Chaque opération doit se terminer avant que la suivante ne commence. Le code asynchrone permet de lancer des opérations longues (requêtes réseau, lectures de fichiers) sans bloquer l'exécution du reste du code.

```javascript
// Synchrone
console.log("Début");
const resultat = 1 + 2;
console.log("Résultat :", resultat);
console.log("Fin");
// Affiche : Début, Résultat : 3, Fin
```

```javascript
// Asynchrone (setTimeout)
console.log("Début");
setTimeout(() => {
  console.log("Délai terminé");
}, 1000);
console.log("Fin");
// Affiche : Début, Fin, Délai terminé (après 1 seconde)
```

<Callout type="info">
JavaScript est single-threaded : il n'a qu'un seul thread d'exécution. Le code asynchrone ne crée pas de threads supplémentaires, mais utilise un mécanisme de boucle d'événements pour gérer les opérations asynchrones.
</Callout>

### Callbacks

Les callbacks sont des fonctions passées en paramètre à d'autres fonctions, pour être exécutées une fois l'opération asynchrone terminée. C'est l'approche historique de la programmation asynchrone en JavaScript.

```javascript
function faireAsynchrone(callback) {
  setTimeout(() => {
    callback("Opération terminée");
  }, 1000);
}

faireAsynchrone((resultat) => {
  console.log(resultat); // "Opération terminée"
});
```

**Callback hell** : l'imbrication excessive de callbacks rend le code difficile à lire et à maintenir.

```javascript
faireAsynchrone((resultat1) => {
  faireAutreAsynchrone(resultat1, (resultat2) => {
    faireEncoreAsynchrone(resultat2, (resultat3) => {
      console.log(resultat3);
    });
  });
});
```

<Callout type="warn">
Évitez les callbacks imbriqués (callback hell). Utilisez des promesses ou async/await pour un code asynchrone plus lisible.
</Callout>

### Promesses (Promises)

Les promesses (ES2015) sont des objets qui représentent l'état final d'une opération asynchrone. Une promesse peut être dans l'un de trois états :

- **Pending** : en attente, l'opération n'est pas terminée.
- **Fulfilled** : réussie, l'opération s'est terminée avec succès.
- **Rejected** : échouée, l'opération a échoué.

```javascript
const promesse = new Promise((resolve, reject) => {
  setTimeout(() => {
    const succes = Math.random() > 0.5;
    if (succes) {
      resolve("Opération réussie");
    } else {
      reject("Opération échouée");
    }
  }, 1000);
});
```

**then, catch, finally** : méthodes pour gérer le résultat d'une promesse.

```javascript
promesse
  .then((resultat) => {
    console.log("Succès :", resultat);
  })
  .catch((erreur) => {
    console.log("Erreur :", erreur);
  })
  .finally(() => {
    console.log("Terminé (succès ou échec)");
  });
```

`then` est exécuté si la promesse est fulfilled. `catch` est exécuté si la promesse est rejected. `finally` est toujours exécuté, quel que soit le résultat.

**Chaînage de promesses** : `then` renvoie une nouvelle promesse, ce qui permet de chaîner plusieurs opérations asynchrones.

```javascript
fetch("https://api.example.com/data")
  .then((response) => response.json())
  .then((data) => console.log(data))
  .catch((erreur) => console.error(erreur));
```

**Promise.all** : attend que plusieurs promesses soient terminées.

```javascript
const promesse1 = fetch("https://api.example.com/data1");
const promesse2 = fetch("https://api.example.com/data2");

Promise.all([promesse1, promesse2])
  .then((responses) => console.log(responses))
  .catch((erreur) => console.error(erreur));
```

**Promise.race** : renvoie la première promesse terminée (succès ou échec).

```javascript
const promesse1 = new Promise((resolve) => setTimeout(() => resolve("A"), 100));
const promesse2 = new Promise((resolve) => setTimeout(() => resolve("B"), 200));

Promise.race([promesse1, promesse2])
  .then((resultat) => console.log(resultat)); // "A"
```

### async/await

`async/await` (ES2017) est une syntaxe sucre pour travailler avec les promesses de manière synchrone. Une fonction marquée `async` renvoie toujours une promesse. `await` met en pause l'exécution de la fonction jusqu'à ce que la promesse soit résolue.

```javascript
async function obtenirDonnees() {
  try {
    const response = await fetch("https://api.example.com/data");
    const data = await response.json();
    console.log(data);
  } catch (erreur) {
    console.error(erreur);
  }
}

obtenirDonnees();
```

`async/await` rend le code asynchrone plus lisible en évitant les chaînes de `then`. Le code ressemble à du code synchrone, ce qui facilite la compréhension et le débogage.

<Callout type="tip">
Utilisez `try/catch` avec `async/await` pour gérer les erreurs. C'est plus lisible que d'enchaîner plusieurs `.catch()`.
</Callout>

### API Fetch

L'API fetch (ES2015) est l'interface moderne pour effectuer des requêtes HTTP en JavaScript. Elle remplace l'ancien `XMLHttpRequest` (XHR) et est basée sur les promesses.

**Requête GET simple** :

```javascript
fetch("https://api.example.com/data")
  .then((response) => response.json())
  .then((data) => console.log(data))
  .catch((erreur) => console.error(erreur));
```

**Requête POST avec données** :

```javascript
fetch("https://api.example.com/data", {
  method: "POST",
  headers: {
    "Content-Type": "application/json",
  },
  body: JSON.stringify({ nom: "Jean", age: 30 }),
})
  .then((response) => response.json())
  .then((data) => console.log(data))
  .catch((erreur) => console.error(erreur));
```

**Options de fetch** :

```javascript
fetch("https://api.example.com/data", {
  method: "GET",
  headers: {
    "Authorization": "Bearer token",
    "Content-Type": "application/json",
  },
  mode: "cors", // ou "same-origin", "no-cors"
  cache: "no-cache",
});
```

**Response** : l'objet response contient des informations sur la réponse HTTP.

```javascript
fetch("https://api.example.com/data")
  .then((response) => {
    console.log(response.status); // Code de statut (200, 404, etc.)
    console.log(response.ok); // true si status est dans 200-299
    console.log(response.headers.get("Content-Type"));
    return response.json();
  });
```

### Gestion des erreurs

La gestion des erreurs asynchrones est essentielle pour créer des applications robustes. Il existe plusieurs approches.

**try/catch avec async/await** :

```javascript
async function obtenirDonnees() {
  try {
    const response = await fetch("https://api.example.com/data");
    if (!response.ok) {
      throw new Error(`Erreur HTTP : ${response.status}`);
    }
    const data = await response.json();
    return data;
  } catch (erreur) {
    console.error("Erreur lors de la récupération :", erreur);
    throw erreur; // Rejette l'erreur pour la gérer plus haut
  }
}
```

**catch avec promesses** :

```javascript
fetch("https://api.example.com/data")
  .then((response) => {
    if (!response.ok) {
      throw new Error(`Erreur HTTP : ${response.status}`);
    }
    return response.json();
  })
  .then((data) => console.log(data))
  .catch((erreur) => console.error(erreur));
```

**finally** : exécuté que la promesse soit résolue ou rejetée. Utile pour le nettoyage (masquer un loader).

```javascript
fetch("https://api.example.com/data")
  .then((response) => response.json())
  .then((data) => console.log(data))
  .catch((erreur) => console.error(erreur))
  .finally(() => {
    console.log("Requête terminée");
  });
```

### CORS

CORS (Cross-Origin Resource Sharing) est un mécanisme de sécurité du navigateur qui restreint les requêtes HTTP entre origines différentes. L'origine est définie par le protocole, le domaine et le port (ex: `https://example.com:443`).

**Politique same-origin** : par défaut, le navigateur autorise uniquement les requêtes vers la même origine que la page actuelle.

```javascript
// Sur https://example.com
fetch("https://example.com/api/data"); // Autorisé (même origine)
fetch("https://api.autre.com/data"); // Bloqué par CORS (origine différente)
```

**Requête CORS** : pour autoriser les requêtes cross-origin, le serveur doit envoyer les en-têtes CORS appropriés.

```http
Access-Control-Allow-Origin: https://example.com
Access-Control-Allow-Methods: GET, POST
Access-Control-Allow-Headers: Content-Type
```

**Requête préflight (OPTIONS)** : pour certaines requêtes (POST avec JSON, ou avec en-têtes personnalisés), le navigateur envoie d'abord une requête OPTIONS pour vérifier que le serveur autorise la requête.

<Callout type="info">
CORS est une restriction du navigateur, pas du serveur. Le serveur peut autoriser CORS en envoyant les en-têtes appropriés, mais le navigateur applique toujours la restriction.
</Callout>

## Erreurs fréquentes

**Oublier await devant une promesse**

```javascript
async function obtenirDonnees() {
  const response = fetch("https://api.example.com/data");
  const data = response.json(); // Promesse non awaitée
  console.log(data); // Promise {<pending>}
}
```

Sans `await`, la fonction renvoie une promesse en attente au lieu de la donnée résolue.

<Callout type="warn">
```javascript
async function obtenirDonnees() {
  const response = await fetch("https://api.example.com/data");
  const data = await response.json();
  console.log(data);
}
```
Toujours utiliser `await` devant les appels asynchrones (fetch, response.json(), etc.) dans une fonction async.
</Callout>

**Oublier try/catch avec async/await**

```javascript
async function obtenirDonnees() {
  const response = await fetch("https://api.example.com/data");
  const data = await response.json();
  return data;
  // Si une erreur survient, elle n'est pas capturée
}
```

Les erreurs asynchrones ne sont pas capturées par try/catch englobant. Chaque appel async/await doit être dans son propre try/catch.

<Callout type="warn">
```javascript
async function obtenirDonnees() {
  try {
    const response = await fetch("https://api.example.com/data");
    const data = await response.json();
    return data;
  } catch (erreur) {
    console.error(erreur);
    throw erreur;
  }
}
```
Enveloppez le code asynchrone dans try/catch pour capturer les erreurs. Vous pouvez également laisser les erreurs se propager pour les gérer à un niveau supérieur.
</Callout>

**Ne pas vérifier response.ok**

```javascript
fetch("https://api.example.com/data")
  .then((response) => response.json())
  .then((data) => console.log(data));
```

Si le serveur renvoie une erreur (ex: 404 Not Found), `response.json()` échouera car le corps n'est pas du JSON valide.

<Callout type="warn">
```javascript
fetch("https://api.example.com/data")
  .then((response) => {
    if (!response.ok) {
      throw new Error(`Erreur HTTP : ${response.status}`);
    }
    return response.json();
  })
  .then((data) => console.log(data))
  .catch((erreur) => console.error(erreur));
```
Vérifiez toujours `response.ok` avant de traiter la réponse. `ok` est true pour les codes de statut 200-299.
</Callout>

**Utiliser setTimeout dans du code asynchrone**

```javascript
setTimeout(() => {
  console.log("Délai terminé");
}, 1000);
console.log("Ce code s'exécute tout de suite");
```

Le code après `setTimeout` s'exécute immédiatement, pas après le délai. C'est le comportement normal de JavaScript asynchrone.

<Callout type="warn">
```javascript
setTimeout(() => {
  console.log("Délai terminé");
}, 1000);
console.log("Ce code s'exécute tout de suite");
```
Si vous avez besoin que le code s'exécute après le délai, placez-le à l'intérieur du callback. Pour un code asynchrone lisible, utilisez `await new Promise(...)` ou la fonction `delay`.
</Callout>

<Exercise n="9.6" title='Gérer les erreurs de réseau'>
Créez une fonction `obtenirDonneesAvecRetry(url, maxRetries)` qui tente de récupérer des données jusqu'à `maxRetries` fois en cas d'échec. La fonction doit :

1. Attendre 1 seconde entre chaque tentative
2. Retourner les données dès que la requête réussit
3. Renvoyer une erreur après toutes les tentatives
</Exercise>

<Solution>
```javascript
async function obtenirDonneesAvecRetry(url, maxRetries = 3) {
  let lastError;

  for (let i = 0; i < maxRetries; i++) {
    try {
      const response = await fetch(url);
      if (!response.ok) {
        throw new Error(`Erreur HTTP : ${response.status}`);
      }
      const data = await response.json();
      return data;
    } catch (erreur) {
      lastError = erreur;
      console.log(`Tentative ${i + 1}/${maxRetries} échouée, nouvelle tentative dans 1 seconde...`);
      await new Promise((resolve) => setTimeout(resolve, 1000));
    }
  }

  throw new Error(`Échec après ${maxRetries} tentatives : ${lastError.message}`);
}

// Test
obtenirDonneesAvecRetry("https://jsonplaceholder.typicode.com/posts/1", 3)
  .then((data) => console.log("Données :", data))
  .catch((erreur) => console.error(erreur));
```
</Solution>

<Exercise n="9.8" title='Défi : Application météo'>
Créez une application météo qui utilise une API réelle (ex: OpenWeatherMap). L'application doit :

1. Demander à l'utilisateur d'entrer un nom de ville
2. Envoyer une requête à l'API météo
3. Afficher la température actuelle, la description, et l'humidité
4. Gérer les erreurs (ville introuvable, erreur réseau, erreur API)
5. Afficher un message de chargement pendant la requête

Utilisez async/await, try/catch, et la délégation d'événements pour les interactions. Note : vous aurez besoin d'une clé API pour OpenWeatherMap.
</Exercise>

<Solution>
```javascript
const API_KEY = "VOTRE_CLE_API"; // Remplacez par votre clé
const API_URL = "https://api.openweathermap.org/data/2.5/weather";

// Sélection des éléments
const input = document.querySelector("#ville");
const bouton = document.querySelector("#rechercher");
const resultat = document.querySelector("#resultat");
const loader = document.querySelector("#loader");

// Fonction pour récupérer la météo
async function obtenirMeteo(ville) {
  try {
    loader.style.display = "block";
    resultat.style.display = "none";

    const url = `${API_URL}?q=${ville}&appid=${API_KEY}&units=metric&lang=fr`;
    const response = await fetch(url);

    if (!response.ok) {
      throw new Error(`Erreur HTTP : ${response.status}`);
    }

    const data = await response.json();

    if (data.cod !== 200) {
      throw new Error(data.message);
    }

    afficherResultat(data);
  } catch (erreur) {
    console.error("Erreur :", erreur);
    resultat.textContent = `Erreur : ${erreur.message}`;
    resultat.style.display = "block";
  } finally {
    loader.style.display = "none";
  }
}

// Fonction pour afficher le résultat
function afficherResultat(data) {
  const temperature = data.main.temp;
  const description = data.weather[0].description;
  const humidite = data.main.humidity;

  resultat.innerHTML = `
    <h2>Météo à ${data.name}</h2>
    <p><strong>Température :</strong> ${temperature}°C</p>
    <p><strong>Description :</strong> ${description}</p>
    <p><strong>Humidité :</strong> ${humidite}%</p>
  `;
  resultat.style.display = "block";
}

// Écouteur d'événement
bouton.addEventListener("click", () => {
  const ville = input.value.trim();
  if (ville) {
    obtenirMeteo(ville);
  } else {
    resultat.textContent = "Veuillez entrer une ville";
    resultat.style.display = "block";
  }
});

// Écouteur sur l'input pour permettre la recherche avec Entrée
input.addEventListener("keypress", (event) => {
  if (event.key === "Enter") {
    bouton.click();
  }
});
```

```html
<button id="rechercher">Rechercher</button>
<div id="loader" style="display: none;">Chargement...</div>
<div id="resultat" style="display: none;"></div>
```
</Solution>
